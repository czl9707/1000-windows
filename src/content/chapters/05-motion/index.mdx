[The layers](/docs/the-layers) fixed the division of labour: geometry emits
marks, motion places them, style dresses them, the pen draws them. This
chapter is the placing. Motion owns one concern — where a mark's points land
on the canvas — and one input — depth. It owns no colour, no tremor, no
randomness of its own.

Move the pointer across the canvas: the wall planes hold still and the

for the one input the finished wall will use instead: where this canvas
sits relative to the screen.

## Weak perspective

Placement is a projection from the marks' 3D points — `x`, `y` in unit
measure, `z` the depth with `0` the wall plane — down to the 2D points the
pen draws. The reference's raum chapter supplies the model, and it survives
whole: weak perspective, scale growing as a point stands nearer the viewer,

```ts
const FOCAL = 30;

export interface Projection {
  project(pts: Pt3[]): Pt[];
  scaleAt(z: number): number;
}

export function makeProjection(eye: Eye, focal: number = FOCAL): Projection {
  const scaleAt = (z: number): number => focal / (focal - z);
  return {
    project: (pts) =>
      pts.map((p) => {
        const s = scaleAt(p.z);
        return { x: p.x * s + eye.x * (s - 1), y: p.y * s + eye.y * (s - 1) };
      }),
    scaleAt,
  };
}
```

The focal length lives inside the projection module — no caller names or
passes it; the builder keeps the default, and only the demo's slider
supplies its own. The demo's Focal slider sweeps the length from `2` to
`50`; the engine default is `30`. At `30`, an add-on standing `0.4` in
front of the wall magnifies by about `1.3%`, and the deepest mark there
is — a casement leaf swung fully open, reaching past `1.1` — by under
`4%`. Depth reads through placement and parallax; a depth error never
gets the chance to read as a drawing error. Stroke widths scale by the
mark's mean depth (`width · projection.scaleAt(meanZ)`), so a nearer
sill draws its line a touch heavier, the way it would if you stood
closer to it.

## The eye sits at the screen's centre

The parallax needs a viewpoint, and the choice is structural: the eye is
always the screen's centre. The pointer never becomes the eye; panning the
wall never moves it. What moves is the canvas — on the finished home page
each viewport of the wall sits at its own offset from the screen's centre,
and every mark in it is drawn as seen from that one fixed point.

The projection is built from that offset once per frame, the way the
palette is built from the theme's colours — `makeProjection(eye)` — and
lands each point as the eye sees it. A point at wall position `p` and
depth `z` projects to `(p + eye) · s`; drawn back in the canvas's own
frame, with the canvas pinned where it sits on screen, that is

```ts
export function makeProjection(eye: Eye, focal: number = FOCAL): Projection {
  const scaleAt = (z: number): number => focal / (focal - z);
  return {
    project: (pts) =>
      pts.map((p) => {
        const s = scaleAt(p.z);
        return { x: p.x * s + eye.x * (s - 1), y: p.y * s + eye.y * (s - 1) };
      }),
    scaleAt,
  };
}
```

The eye enters only as `eye · (s − 1)`. On the wall plane `s` is exactly
`1`, so the eye term vanishes: the wall itself is pinned, and a window's
frame never moves a pixel of parallax — its identity hangs on world-grid
coordinates, and those coordinates just promised the same tenant however
the camera arrived. Depth is the only thing the eye can move, and it moves
it away from the screen's centre: a canvas sitting right of centre draws
its near layers further right, the way anything nearer than a wall reads
when you look off-axis.

The demo maps the pointer to the eye by the simplest honest rule: the
cursor at the canvas's edge reads as the strip sitting at the screen's
edge, so the eye offset spans the canvas's own unit span. On the wall
every window feeds the same term from its own position — its world
coordinates minus the camera, seen from that one fixed point — and the
pointer drops out of the picture entirely.

## What it costs

One multiply-add per point per axis, inside a projection the draw stage
already runs every frame. No extra sort, no second pass, no per-mark state:
the eye and the focal length are two values handed down with the palette.
